# ADR-0010: Versioned bundle-size snapshot schema

## Context

A PR-level bundle-size budget (`size measure` / `size diff`) compares a measurement taken on a
PR's base against one taken on its head. The two are produced by different CI runs, possibly days
apart, and the tools that feed them (Metro's source-map output, Hermes' compiler) change between
versions. Comparing two snapshots produced under different assumptions would make a toolchain
upgrade look like a size regression, or hide a real one.

## Decision

- Measurements are stored as a `BundleSnapshot` (`src/types/bundleSize.ts`) with an explicit
  `schemaVersion`, the `platform`, and the Metro/Hermes versions that produced it.
- `diffBundleSnapshots()` refuses to compare (`status: 'not-comparable'`, with a reason) when the
  schema version or platform differs, or when both sides record a *known* Metro/Hermes version
  and they differ. Callers treat that the same as a missing baseline: re-measure the base, never
  compare unlike data.
- A toolchain version that could not be determined is `null`, never a guess (ADR-0004). A `null`
  on either side still compares, but the result carries a warning.
- Hermes bytecode size is `null` when no `.hbc` was measured; a `totalHbcKb` budget is then
  reported as not-checked rather than passed.
- Per-module sizes are *generated bytes attributed through the source map*, keyed by a
  project-root-relative POSIX path. They are an attribution estimate, not exact minified sizes.
- The CLI never runs `expo export`, Metro or `hermesc` itself. `size measure` only reads
  artifacts the CI job already built (bundle + source map, optional `.hbc`), keeping to the rule
  that scanned-repository tooling is not executed in the main process.

## Alternatives considered

- Reading Expo Atlas exports as the primary source — rejected for now: format stability is
  unverified. Source maps are a standard format; Atlas can be an optional adapter later.
- Having the CLI invoke the build — rejected: it executes project build tooling (enhanced
  security-review path) and makes measurements depend on the machine running the CLI.
- No schema version, comparing best-effort — rejected: silent apples-to-oranges comparison is the
  failure this feature exists to prevent.

## Consequences

- Any change to `BundleSnapshot`'s shape bumps `BUNDLE_SNAPSHOT_SCHEMA_VERSION`; old baselines
  then force a base re-measure instead of a wrong diff.
- The GitHub Action and CLI share this one contract.

## Status

Accepted
